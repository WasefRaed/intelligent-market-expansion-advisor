# Phase 5 — Reviewed Sources and Evidence Provenance

**Reviewed:** 2026-10-09. The source registry is deliberately offline; using it requires **zero API calls**. It is NOT automated Google Search and NOT a guarantee that a web page has not changed since review.

## What changed

- `data/source_registry.json`: small, auditable list of human-reviewed authoritative sources with stable ID, precise supported claim, URL, limits, and review date.
- `app/evidence_registry.py`: validates registry integrity and selects only source notes relevant to a user question; no web traffic.
- `app/advisory_service.py`: injects narrow source notes in the model context and **adds a separate, deterministic reference section** to AI responses. Any unrelated AI reasoning remains hypothetical and unverified.
- `app/ui.py`: source catalog displays review date, supported claim, and limits. Original snapshot links are separately labeled as unreviewed research leads.
- `tests/test_evidence_registry.py`: offline provenance and scope checks.

## Example: regulatory notes

The Federal Tax Authority VAT registration source describes AED 375,000 in relevant taxable supplies/imports for the specified resident-business test. It is **not** proof of this client's registration status.

The FTA Corporate Tax general guide describes the ordinary taxable-income rate bands (0% to AED 375,000; 9% above). This threshold is **not a turnover threshold or a universal registration threshold**. For CT registration, use the separate FTA registration source.

For food establishments, Dubai Municipality publishes food-establishment requirements, while the UAE government portal identifies the Abu Dhabi Agriculture and Food Safety Authority for Abu Dhabi food safety. **No supplied evidence proves a specific property is approved.**

## Example: location notes

Visit Dubai describes JLT's mix of towers, offices, residences, hotels, dining and pedestrian access. Experience Abu Dhabi describes Al Zahiyah's central established setting. Neither verifies footfall, rent, landlord terms, restaurant demand, sales projections or which city is commercially superior.

## How to extend the registry safely

1. Open and inspect the actual official page, rather than trusting a previously copied citation.
2. Add a **single narrow supported claim**, the correct original URL, limitations and a review date. Do not put generalized conclusions like "best area for our restaurant" in a source claim.
3. Update `selected_references` only for questions to which the page is relevant. Keep the agent input compact to minimize token usage.
4. Add a regression test to ensure this source is selected for appropriate queries and absent from unrelated queries.
5. Rerun `python -m pytest -q` and inspect the resulting citations in the GUI.

## Still not implemented / still requiring independent validation

- Live continuously refreshed search, external URL harvesting, publication-date checks on every request, and page-content change detection.
- Verified competitor menus and prices in each neighborhood; current operating status and delivery-platform fees.
- Site-level real-estate quotes, measured pedestrian counts, customer surveys, occupancy costs, or license approvals.
- Model-output-level fact checking of every sentence. The deterministic appended notes are independently maintained; they do **not** validate unrelated sentences generated by Gemini.

## API quota

The tested Gemini 3.6 Flash free-tier project displayed a 429 day-limit of 20 requests per model in the user's environment. A temporary 503 and a daily 429 are different errors. Do not continuously retry a confirmed daily limit; check the specific reset in Google AI Studio. The source catalog, location rankings and financial calculator can be demonstrated without an API key.
